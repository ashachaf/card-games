# Game page anatomy

Every game follows the same order, so a reader who has learned one page knows them all. The template is `schema/game.schema.json`, and the build's check enforces it. Wording rules are in `hebrew-style`, drawings in `card-visuals`.

## Identity and metadata (top of the page and the game card in the list)
| Field | What | Rule |
|---|---|---|
| `id` | English name, lowercase with dashes | Never changes after publishing: it's the URL |
| `name` | The name Israelis use | |
| `aliases` | Other names, shown under the title | English first |
| `keywords` | Search only, not shown | Old or competing names |
| `hook` | What the game is and why it's fun | 1–2 sentences, up to 160 characters |
| `players` / `best` | `[min, max]` / "3–5" | The base game, not a variant |
| `minutes` | `[min, max]` | One round, or a whole game when that's the natural unit |
| `difficulty` | 1 easy, 2 medium, 3 hard | Sets the sort order and whether `inShort` is required |
| `age` | "6+" | Drinking games "18+" |
| `deck` / `deckType` / `decks` | What to bring, in words / standard, jokers, stripped / number or range | Mention removed cards and props (tokens, spoons) |
| `tags` | 2–6 from `i18n/he.json` | Never `drinking`, which is added automatically |

## The body, in page order
1. **`goal`:** how you win or lose, in 1–2 sentences.
2. **`inShort`:** 2–4 sentences that explain the whole game with no jargon. **Required** at difficulty 3. **Recommended** when `turn` has more than 6 steps, or the game has several stages.
3. **`glossary`:** `[word, meaning]` for every term of art used on the page (trick, trump, run, pile). Required as soon as there's such a term.
4. **`values` / `valuesNote`:** rank and point values, and special cards. Skip when every card is plain.
5. **`setup`:** `steps` (deal, middle of the table, who starts and which direction) plus one `visual` of the deal.
6. **`turn`:** one action per step, in the order of play. Each step is one sentence or two. Add a drawing where it helps (see `card-visuals`). Special-card rules go in their own step, not inside a long one.
7. **`combos`:** scoring combinations or a hand ranking, with a drawing each. Use `title` for a different heading ("דירוג הידיים").
8. **`scoring` / `scoringVisual`:** how a round ends, how the game ends, and how to count. Optionally one drawing of a full count.
9. **`example`:** 3–5 paragraphs. One real round, with names and real cards, in turn order, including **one moment where a rule matters** (a challenge, a mistake, a special card). Every number and card must add up and agree with the rules on the page.
10. **`tips`:** 2–4 tips that help you play better, not repeats of the rules.
11. **`mistakes`:** 2–3 mistakes beginners really make, each with the correct way.
12. **`variants`:** `[name, text]`. Common house rules, a version for young kids, a longer or shorter version.
13. **`sober`:** required when `drinkingGame: true`. 2–4 rules for playing without drinking.
14. **`drinking`:** optional on a regular game. 2–5 sip rules on top of the regular game.
15. **`video`:** a YouTube search phrase, not a link.

Similar games, the text version, the sitemap and the structured data are all generated by the build. You don't write them.

## A new field?
Only if the page really needs it. Add it in the same change to the schema, the build's validation, `gameHTML` in `site/app.js`, the text page in `build.mjs`, this skill and `CONTRIBUTING.md`. See `change-site`.
